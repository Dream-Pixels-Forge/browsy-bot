# v0.6.0 — Ecosystem & operational polish (CI action, retry, popups/iframes)

## Objective
Operationalize browsy-bot for team CI/CD: a GitHub Action that validates UI on
PRs, built-in retry/resilience for flaky selectors, and robust popup/iframe
handling so complex SPAs just work.

## Context
The core capabilities are complete by v0.5.0. v0.6.0 wraps them in
production-ready packaging: a `browsy-validate` GitHub Action, declarative retry
with snapshot+retry semantics, and iframe/popup traversal that removes the last
manual targetId juggling.

## Deliverables
- [ ] `.github/workflows/browsy-validate.yml` + `src/action.ts` (or composite
      action): run `browsy doctor`, capture screenshots on failure, upload
      `dev-notes/browsy-captures/` as workflow artifacts.
- [ ] `src/core/retry.ts` — `retryableAction(session, fn, options?)`:
      exponential backoff, snapshot-before-retry, max attempts, captures to
      `dev-notes/browsy-captures/retries/` on each attempt.
- [ ] `src/core/frames.ts` — `enterFrame(session, selector)` /
      `exitFrame(session)`: resolve iframe DOM nodes, switch CDP session
      target to the frame, restore on exit. Popup auto-switch via
      `Target.targetCreated`.
- [ ] `src/actions.ts` — wire retry/frames into the public surface.
- [ ] `src/mcp.ts` — `browsy_retry`, `browsy_enter_frame`, `browsy_exit_frame`
      tools.
- [ ] `src/cli.ts` — `browsy retry`, `browsy enter-frame`, `browsy exit-frame`
      commands.
- [ ] Tests: test/action.test.ts (workflow renders), test/retry.test.ts,
      test/frames.test.ts.
- [ ] Done when: `npm run typecheck && npm run build && npm test` all green.

## Risks
- GitHub Action needs `node20` + `browsy` binary or `npx browsy-bot@latest`; document install.
- Frame switching requires `DOM.getFrameOwner` / `Page.getFrameTree`; nested frames need recursion depth guard.
- Retry must not mask real bugs; default max attempts low (3) with clear backoff.
