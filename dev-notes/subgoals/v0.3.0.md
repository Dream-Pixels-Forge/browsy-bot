# v0.3.0 — Core interaction gaps (dialogs, uploads, downloads, network idle)

## Objective
Ship the four most-requested browser automation primitives that teams currently
need Playwright/Puppeteer for: dialog handling, file upload, file download, and
waitForNetworkIdle. All implemented directly over CDP (no middleware).

## Context
Browsy-bot's zero-middleware CDP core is solid, but real E2E flows hit walls
when a page triggers an `alert`/`confirm`/`prompt`, needs a file upload, starts
a download, or navigates a SPA that settles via network idle rather than DOM
presence. These are the #1 reasons teams abandon a "lightweight CDP" tool.

## Deliverables
- [ ] `src/core/dialogs.ts` — `acceptDialog(session)` / `dismissDialog(session)` +
      `dialogText(session)`: listen for `Page.javascriptDialogOpening`, answer
      via `Page.handleJavaScriptDialog`. Expose `browsy_dialog` (MCP/CLI).
- [ ] `src/core/upload.ts` — `setFileInput(session, selector, filePaths)`:
      resolve `<input type="file">` via DOM, call `DOM.setFileInputFiles`.
- [ ] `src/core/download.ts` — `setDownloadBehavior(session, behavior, dir)`:
      `Browser.setDownloadBehavior`, capture download events, write to
      `dev-notes/browsy-captures/downloads/` (or explicit dir).
- [ ] `src/core/idle.ts` — `waitForNetworkIdle(session, options?)`:
      track `Network.requestWillBeSent`/`Network.responseReceived`,
      resolve when no requests in flight for `idleMs` (default 500), cap at
      `timeoutMs`.
- [ ] `src/actions.ts` — wire dialogs/upload/download/idle into the public
      action surface.
- [ ] `src/mcp.ts` — `browsy_dialog`, `browsy_upload`, `browsy_download`,
      `browsy_wait_idle` tools.
- [ ] `src/cli.ts` — `browsy dialog`, `browsy upload`, `browsy download`,
      `browsy wait-idle` commands.
- [ ] Tests: test/dialogs.test.ts, test/upload.test.ts, test/download.test.ts,
      test/idle.test.ts (all with mocked CDP transport, no Chrome).
- [ ] Done when: `npm run typecheck && npm run build && npm test` all green.

## Risks
- Dialog events fire on a separate CDP domain; ensure `Page.enable`/`Page.setInterceptFileChooserDialog` is enabled per session.
- Downloads can be large; cap file size and stream to disk rather than buffering in memory.
- `setFileInputFiles` requires resolved DOM node ids; handle "not found" with actionable error.
