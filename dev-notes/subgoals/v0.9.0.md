# v0.9.0 — Structural visual diff

## Objective
Add a DOM-structure visual diff that compares two page snapshots structurally
(tag names, attributes, text content, element counts) rather than pixel-by-pixel.
This is more robust than pixel diff for dynamic content, animations, and
anti-aliasing, and pairs with the existing pixel diff as a complementary check.

## Context
browsy-bot already has pixel-based visual regression (v0.4.0). Pixel diff is
brittle: font rendering, sub-pixel positioning, GIF animations, and dynamic
timestamps cause false positives. A structural DOM diff captures real
regressions (missing elements, changed classes, removed text) without noise.

## Deliverables
- [x] `src/core/dom-diff.ts` — `captureDomSnapshot(session)`:
      snapshot the page DOM (tag, id, class, attributes, text, child count,
      visibility, bounding rect). `diffDomSnapshots(a, b)`:
      compute added/removed/changed elements, return pass/fail + diff report.
- [x] `src/core/dom-diff.ts` — `compareDom(session, baselineName)`:
      capture current DOM, compare against a saved baseline JSON file, return
      pass/fail + diff. Baselines stored under
      `dev-notes/browsy-captures/dom-baselines/`.
- [x] `src/core/actions.ts` — wire dom-diff into public surface
- [x] `src/mcp.ts` — `browsy_capture_dom`, `browsy_diff_dom` tools
- [x] `src/cli.ts` — `browsy capture-dom`, `browsy diff-dom` commands
- [x] Tests: test/dom-diff.test.ts, dom-diff tools in mcp.test.ts
- [x] Done when: `npm run typecheck && npm run build && npm test` all green.

## Risks
- Full DOM snapshots can be large on complex pages; consider limiting depth
  or element count.
- Dynamic content (timestamps, random IDs) causes false positives; callers
  should normalize or use stable selectors.
- Visibility/bounding rect requires layout; may be 0 for hidden elements.
