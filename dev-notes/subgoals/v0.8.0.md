# v0.8.0 — Mobile emulation & device simulation

## Objective
Give browsy-bot mobile device emulation so teams can test responsive UI, touch
interactions, geolocation, and device-specific rendering over CDP — without
needing physical devices.

## Context
browsy-bot can drive desktop Chrome, but mobile testing requires device
metrics, user agent, touch events, geolocation, and sensors. v0.8.0 adds
mobile emulation via the CDP `Emulation` domain so screenshots, performance
metrics, and interactions all run against realistic mobile contexts.

## Deliverables
- [x] `src/core/mobile.ts` — `emulateDevice(session, device)`:
      set device metrics (width/height/scale), user agent, touch support via
      `Emulation.setDeviceMetricsOverride` + `Emulation.setUserAgentOverride`
      + `Emulation.setTouchEmulationEnabled`
- [x] `src/core/mobile.ts` — `setGeolocation(session, lat, long, accuracy)`:
      `Emulation.setGeolocationOverride`
- [x] `src/core/mobile.ts` — `setDeviceOrientation(session, alpha, beta, gamma)`:
      `Emulation.setDeviceOrientationOverride`
- [x] Preset device profiles: iPhone, iPad, Pixel, Galaxy, iPad Pro
- [x] `src/core/actions.ts` — wire mobile into public surface
- [x] `src/mcp.ts` — `browsy_emulate_device`, `browsy_set_geolocation`,
      `browsy_set_device_orientation` tools
- [x] `src/cli.ts` — `browsy emulate-device`, `browsy set-geolocation`,
      `browsy set-device-orientation` commands
- [x] Tests: test/mobile.test.ts, mobile tools in mcp.test.ts
- [x] Done when: `npm run typecheck && npm run build && npm test` all green.

## Risks
- `Emulation.setDeviceMetricsOverride` requires page reload to fully apply
  some CSS media queries; document this.
- Touch emulation doesn't replace real touch hardware; note limitations.
- Geolocation override affects all pages in the session.
